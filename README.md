# Image Cache Manager

Консольное приложение на **C# / .NET 8**, демонстрирующее использование трёх паттернов проектирования: **Proxy, Flyweight и Singleton**.

Проект разработан в рамках учебного задания, вариант № 12 — «Менеджер кэша изображений».

## Описание проекта

Image Cache Manager загружает изображения по URL, сохраняет полученные данные в оперативной памяти и повторно использует их при следующих обращениях.

Приложение демонстрирует ленивую загрузку изображений, кэширование и совместное использование настроек для изображений одного типа.

### Основные возможности

- Загрузка изображений по HTTP/HTTPS.
- Ленивая загрузка: изображение скачивается только при первом обращении.
- Повторное использование загруженных данных без повторного HTTP-запроса.
- Хранение изображений в едином кэше.
- Совместное использование настроек изображениями одного типа.
- Подсчёт количества изображений в кэше и общего объёма загруженных данных.
- Демонстрация работы трёх паттернов проектирования.

## Технологии

- **C#**
- **.NET 8**
- `HttpClient` — для загрузки изображений по HTTP/HTTPS.
- `async/await` — для асинхронного выполнения сетевых запросов.
- `Dictionary` — для хранения изображений в кэше.
- `Lazy<T>` — для реализации Singleton.

### Models

Содержит модели данных приложения:

- **ImageType** — перечисление типов изображений: Icon, Banner и Preview.
- **ImageMetadata** — индивидуальные данные изображения: название, URL и тип.
- **ImageSettings** — общие настройки: ширина, высота, цветовая палитра и шрифт подписи.

### Patterns

Содержит реализации паттернов проектирования:

- **ImageProxy.cs** — отвечает за ленивую загрузку изображения и хранение скачанных байтов.
- **ImageCache.cs** — реализует единый кэш изображений.
- **ImageSettingsFactory.cs** — создаёт и повторно использует общие настройки для изображений одного типа.

## Использованные паттерны проектирования

### 1. Proxy — заместитель

Паттерн Proxy управляет доступом к изображению и обеспечивает его ленивую загрузку.

При создании объекта `ImageProxy` изображение ещё не скачивается. Загрузка начинается при первом вызове `DisplayAsync()`.

После успешной загрузки данные сохраняются в памяти. При повторном вызове используются уже загруженные данные.

**Преимущества:**
- Отсутствие ненужных загрузок.
- Повторное использование данных.
- Разделение создания прокси и фактической загрузки изображения.

### 2. Flyweight — приспособленец

Паттерн Flyweight позволяет нескольким изображениям одного типа использовать один объект общих настроек.

Например, баннеры используют одинаковые размеры, палитру и шрифт подписи.

`ImageSettingsFactory` хранит созданные настройки и возвращает существующий объект при повторном запросе для того же типа изображения.

**Преимущества:**
- Сокращение количества одинаковых объектов настроек.
- Повторное использование общих данных.
- Более экономное использование памяти для настроек.

### 3. Singleton — одиночка

Паттерн Singleton обеспечивает доступ к единственному экземпляру `ImageCache`.

Экземпляр создаётся при первом обращении и используется повторно.

Кэш хранит прокси изображений, позволяя возвращать существующий объект при повторном запросе по тому же URL.

**Преимущества:**
- Единая точка доступа к кэшу.
- Предотвращение создания нескольких независимых экземпляров кэша.
- Повторное использование уже созданных прокси.

## Запуск проекта

1. Откройте репозиторий на GitHub.
2. Нажмите **Code → Codespaces**.
3. Создайте Codespace для ветки `main`.
4. Откройте терминал.
5. Перейдите в каталог, содержащий `ImageCacheManager.csproj`, и выполните:

```bash
dotnet run
```

Для работы приложения требуется среда с установленным .NET 8 SDK.

## 🧪 Демонстрация работы

При запуске программа последовательно демонстрирует работу паттернов.

### Singleton

Проверяется, что два обращения к `ImageCache.Instance` возвращают один объект:

```text
Оба обращения возвращают один кэш: True
```

### Proxy

До первого обращения изображение не загружено:

```text
Изображение загружено до первого обращения: False
```

При первом обращении приложение скачивает изображение по URL. При повторном использует данные из памяти:

```text
Изображение загружено: True

Повторное обращение к изображению:
[Proxy] banner1.png уже находится в памяти.
Повторная загрузка не требуется.
```

### Flyweight

Проверяется совместное использование настроек баннерами:

```text
Настройки первого и второго баннеров совпадают: True
Настройки второго и третьего баннеров совпадают: True
```

### Результаты кэширования

Программа показывает количество изображений, число уникальных объектов настроек и общий объём загруженных данных.

Пример результатов:

```text
Количество изображений в кэше: 3
Количество уникальных объектов настроек: 1
Общий объём загруженных данных: 38 060 байт
```

Размер загруженных данных и время загрузки могут отличаться при каждом запуске.

## Результат

В проекте демонстрируется совместная работа трёх паттернов проектирования:

- **Proxy** управляет загрузкой изображений.
- **Flyweight** обеспечивает повторное использование общих настроек.
- **Singleton** предоставляет единый кэш изображений.

Приложение показывает, как эти паттерны могут применяться для организации кэширования и сокращения повторных операций.
